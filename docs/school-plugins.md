# 学校插件：作业、请假与学校活动、学分成绩

三个插件分别对应 App 里的作业Bot（`homework`）、校园Bot（`campus`）和成绩Bot（`grades`）。它们都是 `platforms: [any]`，默认停用，在 App 的设置或 `PATCH /api/v1/plugins/{id}` 里启用。卡片只用 api.md 里已有的类型，App 不用为它们重新编译。

课表是另一个插件 `timetable`：从 Chrome 里打开的学校网站个人日程截图读取，只在 Mac 上运行，见 [timetable.md](timetable.md)。

助理的 `weekly_review`（默认停用、所有平台）每周日汇总待办、作业、课表和活动，结合健康与 Token 写[本周回顾](weekly-review.md)。现有活动记录没有已报名或已参加状态，回顾会明确说明不能确认。

数据从哪来：

- **作业**不另存一份清单，而是从待办里挑出来的。下面三种待办算作业：Agent 用 `homework_mark` 标过的；来源会话在 `course_chats` 里的；标题含作业关键词的（作业、习题、实验报告、课程设计、论文、预习、测验等，`keywords` 可以换成自己的）。在 App 或提醒事项里勾掉待办，作业就算交了。
- **请假和学校活动**由 Agent 在提炼消息时记下：讲座、比赛这类纯通知以前只进摘要，现在同时进 `campus_event_add`；本人的请假申请和审批进度用 `campus_leave_record`。也可以在对话里直接告诉它。通知写明能加多少第二课堂（素拓）学分的，Agent 同时记下分数和类别。
- **推荐参加**：校园Bot 从还能参加的活动里挑出值得报名的，见下面的「推荐参加」卡片。
- **成绩**由 Agent 在读到本人成绩发布时用 `grades_record` 记下，或者从教务系统导出的 CSV 导入（`import_csv`，每小时读一次）。学分、绩点都由代码计算，不交给模型。

Agent 写的每条记录都必须带 `source_refs`（存在的消息 ID），和待办一样不能凭空编来源。提示词里的规则见 `backend/prompts/extract_todos.md` 第 8 步；插件停用时工具随之消失，Agent 跳过这一步。

## 配置

| 插件 | 字段 | 说明 |
| --- | --- | --- |
| homework | `course_chats` | 会话名数组。这些会话里来的待办都算作业，会话名当作课程名 |
| homework | `keywords` | 替换默认的作业关键词 |
| campus | `past_days` | 活动结束后还在「近期活动」里显示几天，默认 3 |
| grades | `required_credits` | 毕业要求的学分，填了才显示「还差多少」 |
| grades | `gpa_scale` | `standard4`（默认：90 分以上 4，80–89 分 3，70–79 分 2，60–69 分 1）、`pku4`（4 − 3(100−x)²/1600）、`linear5`（(x−50)/10）；60 分以下都是 0 |
| grades | `import_csv` | 成绩表 CSV 的绝对路径。表头认「课程名称/课程名/课程」「学分」「总评成绩/总成绩/最终成绩/总评/成绩」「学年学期/开课学期/学期」「课程性质/课程类别/类别」，UTF-8 或 GB18030 编码 |

成绩可以是 0–100 的数字，也可以是「优秀/良好/中等/及格/不及格」「通过/合格/不通过」或 A+ 到 F。「通过」这类只计学分、不计入绩点。学期写成 `2026-2027-1` 这种格式时，卡片上显示为「2026秋」；没给学期时按日期推算（9 月到次年 1 月是第一学期）。

## MCP 工具

参数都放在 `arguments` 对象里。时间是带时区的 ISO 8601；只有日期时写 `YYYY-MM-DD`，表示当地这一天、没有具体时刻（报名截止只写日期时算到当天 23:59）。

| 工具 | arguments | 说明 |
| --- | --- | --- |
| homework_mark | `todo_id`，`course?` | 把已有待办标为作业，可以带课程名 |
| homework_list | `status?`: pending/completed | 作业待办及课程，未完成、截止早的在前 |
| campus_event_add | `title`，`kind?`: 讲座/比赛/报名/会议/考试/文体/志愿/其他，`starts_at?`，`ends_at?`，`place?`，`signup_deadline?`，`note?`，`credits?`（通知写明的第二课堂学分，大于 0、不超过 10），`credit_kind?`（通知里写的类别），`source_refs` | 同名（忽略大小写、空格和标点）且同一天开始的活动只留一条，合并来源；后来的调用只改它给出的字段，标题保留第一次的写法 |
| campus_leave_record | `kind`: 事假/病假/公假/其他，`starts_at`，`ends_at?`，`reason?`，`status?`: 待提交/审批中/已批准/已驳回/已销假（新记录默认审批中），`approver?`，`id?`，`source_refs` | 同一种假、同一天开始的是一条，再记一次就是更新状态；日期变了用 `id` 指定 |
| campus_list | `what`: events/leaves/recommended，`upcoming_only?` | 已有记录，新增前先查；`recommended` 和「推荐参加」卡片同样的顺序，每项多一个 `clash`（冲突的课名或 null） |
| grades_record | `course`，`score`，`credits?`，`term?`，`category?`: 必修/选修/通识/实践/其他，`source_refs` | 同一学期、同一课程是一条，再记一次就是更新 |
| grades_list | `term?` | 各科成绩和绩点，以及卡片上的已修学分、平均绩点、综测和体测（`scores`） |
| grades_score_record | `kind`: 综测/体测/学分，`score?`，`full?`（满分），`required?`（综测和学分：毕业要多少），`source_refs?`（用户在对话里说的可以不填） | 每种只有一条，没给的字段保持原值；学分只记毕业要求，已修学分从成绩算。没记毕业线时用插件设置的 `comprehensive_required`、`required_credits`，满分默认 100 |

## 卡片

`GET /api/v1/plugins/{id}/cards`，按下面的顺序返回。还没有任何数据时，每个插件只返回一张 text 卡片，说明数据会从哪来。

| 插件 | title | type | data |
| --- | --- | --- | --- |
| homework | 这周要交的作业 | stat | `value`：本周（到周日）还没交、还没过截止的作业数；`label`：「最近一项：周六 23:59 · 离散数学作业」或「这周没有要交的作业」；有过了截止还没交的，`delta`「已过截止 2 项」 |
| homework | 还没交 | todo_list | 未完成的作业待办，截止早的在前，最多 20 项 |
| homework | 最近 4 周的作业 | chart | `kind: bar`，按截止时间所在的周计数（没有截止时间的按创建时间），`x` 是那周周一「10/12」，本周是「本周」 |
| homework | 最近交完的 | list | 最近完成的 5 项，`subtitle` 是课程，`detail` 是完成的日子；没有就不返回 |
| campus | 推荐参加 | list | 有可推荐的活动时排第一，最多 5 个。只挑讲座、比赛、报名、文体、志愿、其他这几类（考试和会议不算可选），还没开始、报名也没截止，而且至少有开始时间或报名截止之一。能加第二课堂学分的在前（分多的更前），再按报名截止、开始时间排；和课表上的课时间重叠的放最后（没有结束时间的活动按 1.5 小时算，课表没读到的周按最近读到的一周推测）。`subtitle`「加 0.5 分第二课堂（学术科技） · 周五前报名 · 周六 14:00 · 和「高等数学I（A）」冲突」，`detail` 类别 |
| campus | 请假记录 | list | 最近 6 条，`title`「10月28日 事假」，`subtitle` 原因和审批人，`detail` 状态 |
| campus | 近期活动 | list | 还没结束的活动（结束后再留 `past_days` 天），按开始时间，最多 8 个；`subtitle`「周六 14:00 · 学术报告厅 · 后天前报名」，`detail` 类别 |
| campus | 这周的活动 | stat | `value`：本周还没开始的活动数；还能报名的活动有几个、最早哪天截止写在 `label` |
| grades | 学业进度 | list | 总是返回，刚入学没成绩时也有。`style: rings`，每行带 `progress: {value, max}`，App 画成圆环（旧版 App 是进度条），灰色是满分，彩色是现在的分：平均绩点（`detail`「3.62 / 4」，没考过试是「— / 4」，`subtitle` 换算方式和上学期绩点）；综测（`subtitle`「毕业要 60 分，还差 7.5」）；体测（`subtitle`「离满分差 22」）；已修学分（「86 / 160」，`subtitle`「毕业要 160，还差 74」；毕业要求还没记下时是「0 学分」，`progress` 的 `max` 为 0，整条灰色） |
| grades | 2026秋已出成绩 | list | 最近一个学期的各科成绩，`subtitle`「3 学分 · 必修」，`detail` 成绩（没通过的注明） |
| grades | 各学期绩点 | chart | `kind: bar`，每学期一个点；只有一个学期时不返回 |

## 第二课堂页面（待校准）

学校的「第二课堂成绩单管理系统」网页上有每一类第二课堂学分的进度和可报名的活动。和课表一样，后端只截这个页面的图来读，不登录、不点击，也不调用学校的接口。要用它的接口，需要用户另外明确同意。

读页面需要先校准一次：用户把这个页面停在 Chrome 某个窗口的当前标签页，后端截一张图看清页面结构，再写读取规则。读到以后：

- 「推荐参加」把用户还差学分的类别排在前面。
- 网站上能报名的活动也进推荐。
- 各类第二课堂学分的进度显示在校园Bot 的页面上。

在那之前，推荐只用 QQ 群通知里记下的活动和学分。
