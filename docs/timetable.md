# 课表：截图读取学校网站的个人日程

Windows 原生后端的安装、差别和校准见 [Windows 说明](windows.md)。

插件 `timetable` 从 Chrome 里打开着的学校网站「个人日程」页（`portal.example.edu.cn/#/schedule`）读每天的课。实现在 `backend/plugins/timetable/`。它和作业插件用同一张贴图（作业），所以在 App 里不单独成一个 Bot：课表的卡片排在作业Bot 的页面上，每日文件夹里的 `课程.md` 也归作业Bot。

后端不登录学校网站，也不点、不滚动这个页面：它只截这一个窗口，在本机识别文字，再从文字里读出这一周的课；另外每 10 分钟刷新一次这一页，免得网站因为太久没动静让你重新登录（见下文「自动刷新」）。截图留在本机，进数据库的只有日期、起止时间和课程名。

## 你要做的

1. 在 Chrome 里登录学校网站，打开个人日程，切到「周历」。网站让你重新登录时，登录后回到这一页就行。
2. 让这一页留在一个 Chrome 窗口的**当前标签页**：插件按窗口标题「学校门户-个人日程」找它（Chrome 的窗口标题就是当前标签页的标题）。窗口可以被别的窗口挡住，但不能最小化；表头的星期要露出来，别把页面往下滚。
3. 插件设置里填 `helper`：和 QQ 读取用的是同一个只读截图助手 `~/Library/Application Support/AemeathBot/bin/screen-helper` 的绝对路径。它需要**屏幕录制**权限（见 [deployment.md](deployment.md)）。

想读别的标题的窗口，改设置里的 `page_title`。

## 怎么读

- 启用时读一次，之后每 30 分钟（任务 `plugin:timetable:read`）。
- screen-helper 的 `capture_page` 动作截下标题含 `page_title` 的 Chrome 窗口，`recognize` 用 Apple Vision 识别文字（见 [screen-reading.md](screen-reading.md)）。
- `page.py` 从文字块里读周历：七个星期标签定出七列；日期框（例如 `2026-10-25`）定出是哪一周，并和星期上面的日期数字核对，日期框没读到时只用日期数字；每一列里一个时间段（`08:00-09:35`）加上它下面的几行就是一节课。识别常见的错也改回来：`高等数学|` 改成 `高等数学I`，半角括号改成全角。
- 起点在左侧「个人日程」标签底边以上的是你自己加的日程，其余是课程。
- 每次读到的那一周整周替换：网站上删掉的课，下一次读取后也会消失。

## 自动刷新

学校网站放久了没有动静会让你重新登录。任务 `plugin:timetable:refresh` 每 10 分钟（每小时的 5、15、25…分，在两次读取之间）通过 Chrome 的 AppleScript 刷新标题是 `page_title` 的标签页：

- 只刷新这个标题的标签页，不打开、不切换到 Chrome，也不把它调到前面；Chrome 没开时什么都不做。
- 已经退出登录的页面标题不同，不会被刷新，也不会去登录；这时卡片和助理的提醒照常告诉你课表读不到。
- 刷新后页面显示当周，所以「页面停在旧的一周」也不会再出现。
- 不读密码、不输入任何东西。
- 第一次刷新时 macOS 会问是否允许后端（python）控制「Google Chrome」，点「好」。点了「不允许」的话，到 系统设置 → 隐私与安全性 → 自动化 里打开；一小时后助理会提醒「课表页面没法自动刷新」。
- 如果网站是固定几个小时强制下线（不管有没有动静），刷新也拦不住，需要重新登录。
- 不想要的话，插件设置里关掉 `keep_alive`。

## 页面不会自己翻页

页面一直显示打开（或刷新）时的那一周，所以平时只能读到当周；到了下周、页面还没刷新时，那几天按**最近一次读到的那一周、同一个星期几**推测，卡片、`课程.md` 和工具里都标明「推测」，最多推测 4 周。节假日调课的那几周，推测会不准；你重新登录或刷新页面后读到真实的一周，就以真实的为准。

## 用在哪里

- **每日文件夹**：`每日/<日期>/课程.md`，`今天.md` 分工的第一行（见 [daily-folder.md](daily-folder.md)）。
- **卡片**：今天的课、明天的课（list，`style: timeline`，App 画成时间轴；今天的课标出已经上完的和正在上的，并带 `first`，排在作业Bot 页面最前）；这周课表（text 带 `table`：一行一个开始时间，一列一天，周六周日有课才有那一列，今天那列突出，`footnote` 写什么时候读到哪一周；旧版 App 看到的是每天一行的文字）。没读到时最前面有一张「课表没读到」（也带 `first`），说明原因：页面没打开、不在周历、没有屏幕录制权限等。之前读到的课仍然显示在下面。
- **MCP 工具 `timetable_days`**：`{"from": "2026-10-26", "days": 7}`（都可省略，默认今天起 7 天，最多 14 天），返回每天的课；按推测来的那天带 `estimated_from`（推测所依据那周的周一），完全不知道的那天 `known` 为 false。

## 课前提醒

启用插件后，每次读取都会维护**今天起 7 天（含今天）**的课程日历，使用独立的「AI 课表」日历，事件从上课时间持续到下课时间，不包含「自己的日程」。默认每节课前 15 分钟用苹果日历闹钟提醒，iPhone、Apple Watch 的响铃由系统日历通知负责，不依赖 Aemeath App 的推送。

插件配置 `class_alarm_minutes` 是提前分钟数，默认 `15`，范围 `0–10080`。设为 **`0` 时不写课程事件，并删除之前由这个插件写入的事件**；它表示关闭，不表示上课时响。可以在 `PATCH /api/v1/plugins/timetable` 的 `config` 中设置；配置是完整替换，记得同时保留 `helper` 和自己改过的 `page_title`。

推测出来的课，事件标题后面带「（推测）」，备注写明依据的是哪一周。读到实际那周后，会更新原事件；课名或开始时间改变时，删除旧事件并创建新事件。课程取消、超出这 7 天窗口的旧事件也会删除。页面关闭或读取失败时，仍按已存的课表维护窗口、重试之前失败的日历写入；未知日期不编造课程。

每条课程按日期、开始时间和原课名生成稳定 UUID，插件自己的 `timetable_calendar_events` 表保存写入内容、苹果事件 ID 和上次成功同步的内容。只有内容改变才调用核心注入的 `apple_call`，与待办共用 `core/apple.py` 的 bridge：实机走 Swift，测试走文件假实现。先保存写入意图，成功后保存 ID；失败保留记录，下次读取重试。推测变实读保留同一个 UUID，重复读到相同内容不会每半小时重写。停用插件或后端退出后，已写入苹果日历的事件仍保留；想清空时先把 `class_alarm_minutes` 设为 0，确认同步成功后再停用。

想在日历里单独隐藏课程：

- **iPhone**：打开「日历」App，点底部「日历」，取消勾选 iCloud 下面的「AI 课表」。
- **Mac**：打开「日历」，显示左侧日历列表，取消勾选「AI 课表」。

取消勾选用于隐藏显示；要关闭课前提醒，使用 `class_alarm_minutes: 0`。两个专属日历要放在与 iPhone 同步的 iCloud 账户中，替换 apple-sync 后重新允许日历和提醒事项权限，见 [deployment.md](deployment.md)。

## 出错时

| 运行记录里的错误 | 意思 |
| --- | --- |
| `screen_page_not_open` | 没有标题含「学校门户-个人日程」的 Chrome 窗口：页面关了、切到了别的标签页，或者网站跳到了登录页 |
| `screen_app_not_running` | Chrome 没开 |
| `screen_recording_denied` | screen-helper 没有屏幕录制权限 |
| `timetable_not_week_view` | 窗口里不是周历（月历、列表），或者表头没露出来 |
| `timetable_week_unreadable` | 读不出是哪一周 |
| `timetable_calendar_failed` | 课程已保存在本机，但日历写入或删除失败；检查 apple-sync、日历权限和 iCloud 默认账户，下次读取会重试 |

页面读取的同一个问题连续出现时只记第一次，免得页面关着时每半小时记一条失败；卡片一直显示到问题消失。日历同步失败单独记在作业运行记录中，后续读取会继续重试，不把它显示成页面读取错误。

## 已知限制

- 「个人日程」一行里有两条以上的日程时，第二条可能被当成课程。
- 按标题找窗口：如果另开了一个同样标题的窗口，读的是面积最大的那个。
- 只读周历；月历和列表需要滚动才能看全，没有做。
