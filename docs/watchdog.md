# 数据看门狗

数据源断了要让你马上知道，而不是过了几天才发现。比如 QQ 窗口被关掉、课表页面没开、iPhone 很久没上传健康数据。实现在 `backend/core/watchdog.py`。

## 它看什么

任务 `watchdog` 每 10 分钟看一次下面三类情况。

| 看什么 | 什么时候算断了 |
| --- | --- |
| 每个定时任务的运行记录（`fetch:<插件>`、`plugin:<插件>:<任务>`，以及提炼待办、同步提醒事项、备份、记忆索引、每日文件夹） | 最近一次运行失败，而且 3 小时内没有成功过。从没成功过的任务，从看门狗第一次看到它失败时算起 |
| 插件自己报告的数据 | 插件说的最后一次拿到数据的时间超过它给的时长 |
| 启用了却没能启动的插件 | 马上算 |

第二类是因为有些任务会照常“成功”，其实没拿到数据。比如课表页面没开时，同一个问题只记一次失败；Claude 的登录过期时，读用量的任务也照常结束。目前这几个插件会自己报告：

| 插件 | 报告什么 | 多久没拿到算断了 |
| --- | --- | --- |
| 课表 timetable | 页面读不到了（不管什么原因，也包括读取任务本身的失败） | 3 小时 |
| 课表 timetable | 页面停在旧的一周 | 本周一 0 点起 3 小时 |
| 健康 health | iPhone 上一次上传（`POST /health/samples` 时记下） | 36 小时 |
| 用量 token_usage | Claude 的用量读不到，多半是登录过期、自动续登录也没成功 | 3 小时 |
| QQ / 微信 | 群名被截断没有读的会话；没停在消息列表 | 从看到起 3 小时 |
| QQ / 微信 | 读取中断那天来了消息、又不能按需点开的群（列表上只剩日期） | 看到就提醒 |

插件要报告，就实现一个异步的 `watch()`，返回一个列表，每项包含：

- `key`：小写字母和下划线组成的标识。
- `title`：待办标题。
- `ok_at`：最后一次正常的时间，ISO 格式；不知道时为 `null`，从看门狗第一次看到时算起。
- `hours`：超过多少小时提醒。
- `hint`：用户该怎么处理。
- 可选的 `jobs`：这一项已经覆盖的本插件任务名。这些任务的运行失败就不再单独提醒。

插件不再返回某一项，就算这一项好了。`watch()` 本身出错时，记一条 `plugin:<插件>:watch` 的失败运行，不影响其他检查。

## 怎么提醒

断了的会变成助理Bot的一条待办，截止今天（当地午夜，`has_time=false`），标题如「课表读不到了」「QQ 屏幕读取一直失败」。备注写从什么时候起没成功、该怎么处理。它出现在助理的页面和每日文件夹的 待办.md 里，**只在 App 里，不进手机的提醒事项和日历**（`core/apple.py` 的 `APP_ONLY`），所以不会响铃。以前已经同步到提醒事项的看门狗待办，下一次同步时会从提醒事项里删掉，App 里的那条不动。

- 一个问题只建一条待办；之后原因变了，就更新这条的备注。
- 好了以后，看门狗自己把它勾成完成。
- 你手动勾掉而问题还在，就不再打开，直到它好过一次又断了：同一天再断，会重新打开同一条；之后哪天再断，再建新的一条。你删掉的待办不会被重新打开。
- 待办引用的来源是看门狗自己写的一条消息：插件为 `watchdog`，会话名「数据看门狗」，已标为处理过。它不会被提炼，也不会出现在每日文件夹的 消息.md 里。

状态存在 `kv` 表的 `watchdog` 键：每个问题第一次看到的时间、对应的待办和当时的处理说明。阈值目前写在代码里，不能在 App 里改。
