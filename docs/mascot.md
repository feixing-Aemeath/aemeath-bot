# 插件贴图

每个插件有一张自己的贴图，就像 Grok 里每个 bot 都有自己的形象；不同插件可以是不同的角色，但画风统一（第 3 节）。App 对整张图做动画来表示状态（第 4 节）；带分层图的贴图还会眨眼、看鼠标、和人互动（见「分层效果」），不需要动画帧。

- 贴图目录：`frontend/Design/stickers/`。每张图一个 PNG，文件名（不含 `.png`）就是它的名字。
- 插件用哪张：写在插件 `manifest.yaml` 的 `mascot` 字段里，改一行就能换。
- 还没有贴图的插件：统一显示占位图 `placeholder.png`（灰色的小人，头上一个问号）。

`orange_daisy.png` 不是按第 3 节画的：原图是黑底、没有描边、头发被画面左边切掉的大头像。黑底按颜色抠掉（纯黑背景和角色最暗的眼睛、丝带差得很远），边缘按旁边实色重新算透明度，所以没有黑边或白边；被切掉的左边头发镜像补出几十像素再渐隐，免得圆形头像左边露出一条直边。眼睛是近黑色，分层图用 `swift scripts/sticker-layers.swift --dark-eyes Design/stickers/orange_daisy.png` 生成。

QQ、飞书、微信这些**消息来源**（manifest 的 `provides` 里有 `source` 的插件）只负责读消息，不算角色：Mac App 把它们单独列在「消息来源」下面，用插件的图标（manifest 的 `icon`，SF Symbol 名）而不是贴图。`qq_screen` 的 manifest 里还写着 `red_ribbon`，红蝴蝶结现在是成绩Bot，建议后端把它去掉。

四个角色的插件后端都已实现，manifest 里写好了 `mascot`，卡片和工具见 [school-plugins.md](school-plugins.md) 和 api.md 的 token_usage 一节；App 的模拟数据（`MockBackend`）保留同样的插件，没连上 Mac 时也能看样子。每个角色都可以在 App 里对话（`POST /api/v1/bots/{id}/messages`）。四张新贴图是从一张四宫格角色图裁出来的，裁图脚本是 `frontend/scripts/cut-stickers.swift`（按透明通道切开、每个角色放进 1024 正方形画布）。

强调色用在 Bot 页头部的底色、聊天气泡、状态圆点和徽章这些地方，贴图本身不会被染色。

## 2. 加一张新贴图（不用改代码）

1. 按第 3 节的画风要求出图（第 6 节有提示词），导出 PNG。
2. 放进 `frontend/Design/stickers/<名字>.png`。名字建议直接用插件 id，比如 `feishu.png`；只能用小写字母、数字、`_` 和 `-`，最长 64 个字符。
3. 改这个插件的 `manifest.yaml` 里的一行：

   ```yaml
   mascot: {sticker: feishu, accent: "#22B8CF"}
   ```

   `sticker` 写文件名（不带 `.png`），`accent` 是强调色。不写 `sticker` 就是占位图。
4. 重启后端（`launchctl kickstart -k gui/$(id -u)/local.assistant`），`GET /api/v1/plugins` 就会返回新的 `sticker`。
5. 重新编译 App（Xcode 里重新运行，或者推到 GitHub 让 CI 构建）。整个 `stickers` 文件夹会原样打包进 App，不需要在 Xcode 里一张张添加。

其他情况：

- **换贴图**：只改 manifest 里 `sticker` 那一行，比如把 `health` 的 `lily_veil` 换成 `red_ribbon`。
- **App 自己用哪张**：改 `frontend/Design/stickers/app.json`：

  ```json
  {
    "assistant": {"sticker": "aemeath", "accent": "#E86A9A"},
    "knowledge": {"sticker": "orange_daisy", "accent": "#E57A3C"}
  }
  ```

  `knowledge` 是知识库Bot：manifest 写这张贴图的插件（GoodNotes、课堂照片、视频）都并进她的页面。

- **Bot 叫什么**：名字跟着贴图走，写在 `frontend/Design/stickers/characters.json`：

  ```json
  {"aemeath": "Aemeath Bot", "red_ribbon": "成绩Bot", "lily_veil": "健康Bot"}
  ```

  没写的贴图就用插件名；App 自己的贴图没写名字时叫 Aemeath Bot。
- **一个角色一个 Bot**：几个插件在 manifest 里写同一张贴图，App 就把它们当成同一个角色：只显示一个 Bot（列表里排在前面的那个插件），其他插件的卡片接在它的页面上，简介写成「“作业”与“课表”」。例如作业和课表都是作业。消息来源不合并（QQ 读取和学分成绩都用 red_ribbon，仍是两个）。插件写的是 App 自己的贴图（`app.json` 里的 aemeath）时，它属于助理Bot，卡片排在她页面的最前面，例如天气。
- **贴图文件还没放进来、但 manifest 已经写了名字**：App 显示占位图，不会出错。后端测试 `test_bundled_plugins_declare_their_mascot` 会检查仓库里自带插件写的贴图文件都存在，忘了放图会在 CI 里报出来。
- **检查效果**：Mac App 的「贴图」页（iPhone 是右上角的笑脸按钮）列出 App 里所有贴图在五种状态下的大图和小图。

## 3. 画风要求（所有贴图统一）

| 要点 | 要求 |
| --- | --- |
| 造型 | Q 版大头，没有身体（最多露一点肩膀）。头占画面宽度约 85–95%，像从画面底部探出来 |
| 描边 | 粗描边，整张图一个颜色：深紫灰 `#302840`，或者角色发色最深的那个色，不要纯黑。1024 画布上外轮廓约 20–24 px，内部线（刘海分缕、发饰）约 10–12 px |
| 上色 | 平涂，最多一层阴影（同色系加深约 15%），一两处白色高光；不要渐变阴影、纹理和写实光影（发色本身的渐变可以） |
| 五官 | 大眼睛加腮红；鼻子和嘴可以没有，或者很小 |
| 背景 | **透明**（带透明通道的 PNG），不要白底、不要投影、不要描白边以外的任何背景 |
| 画布 | **正方形**，建议 1024 × 1024（现在两张是 1254 × 1254，也可以）。角色水平居中，左右和上方留约 4% 空白，下方可以直接贴边 |
| 文件 | PNG、sRGB，单张最好不超过 2 MB |
| 区分插件 | 靠角色本身（发色、发型、发饰、配饰）区分，可以带一个和插件有关的小物件。**不要用 QQ、微信、飞书的官方 logo**：不画企鹅，不画两个重叠的绿色气泡，不画飞书的鸟 |

## 4. 状态动画

一共五种状态。动作全部由代码对整张图做位移、缩放、旋转（`MascotPose`，以图片底部中间偏上的位置为轴），出错和离线时在右上角叠加一个小图标。

| 状态 | 动作 | 叠加 |
| --- | --- | --- |
| 待机 `idle` | 每 3 秒一个周期上下浮动（图片高度的 2%），同时轻轻缩放 ±1%，像在呼吸 | 无 |
| 干活中 `working` | 歪头：左右摆 ±6°，1.2 秒一个周期，同时轻微点头 | 无 |
| 完成 `done` | 进入状态时向上弹一下（0.6 秒内升高 8% 再落下，落地时纵向压扁 6%），之后像待机一样浮动；3 秒后自动回到待机 | 无 |
| 出错 `error` | 往下垂（下移 4%、向一侧歪 8°、纵向缩 3%），慢慢小幅摇晃 | 一滴汗，每 2 秒从右上角滑下 |
| 离线 `offline` | 歪 4°，4 秒一个周期慢慢呼吸（缩放 ±1.5%）；颜色变灰（饱和度 40%） | zzz，每 3 秒往上飘 |

### 和 Agent、插件状态的对应关系

| 来源 | 条件 | 贴图状态 |
| --- | --- | --- |
| 后端 | `GET /api/v1/status` 连不上，或 `online=false` | 离线 |
| Agent 运行（`Run`） | `status=running` | 干活中 |
| Agent 运行 | `status=succeeded`，并且结束不到 3 秒 | 完成 |
| Agent 运行 | `status=succeeded`，已经过了 3 秒 | 待机 |
| Agent 运行 | `status=failed` 或 `cancelled` | 出错（一直保持到下一次开始运行或成功） |
| 插件（`PluginView.state`） | `enabled`，没有正在运行的任务 | 待机 |
| 插件 | `enabled`，它的任务（`fetch:<id>`、`plugin:<id>:*`）正在运行 | 干活中 |
| 插件 | `error` | 出错 |
| 插件 | `disabled` 或 `unsupported` | 离线（睡着） |

优先级：离线 > 出错 > 干活中 > 完成 > 待机。代码里的 `MascotState.forRun`、`forPlugin`、`forAssistant` 和 `MascotStateMachine` 实现了这张表，并且有单元测试。

### 减弱动态效果

系统设置里打开「减弱动态效果」（Reduce Motion）后，`MascotView` 不做任何位移、缩放和摆动，只显示这个状态的**静止姿势**：出错时歪 8°，离线时歪 4° 并变灰；汗滴和 zzz 照样显示，但停在固定位置。

### 分层效果：眨眼、看人、互动

贴图可以带一套分层图：在 `stickers/` 里放一个和贴图同名的文件夹（例如 `stickers/aemeath/`），里面四张 PNG，画布大小和位置与整张图完全一致：`base.png`（眼睛用周围的肤色盖掉）、`eyes_open.png`（只有睁开的眼睛，叠在 base 上和原图一模一样）、`eyes_closed.png`（闭眼，每只眼一道向下弯的弧「︶」）、`eyes_mask.png`（可选，眼睛能出现的脸部区域，眼睛往旁边看时会钻到头发下面）。前三张齐了，App 就改用分层动画；没有文件夹的贴图照旧用整张图，只是多了歪头和互动动作。分层图用脚本生成：`swift scripts/sticker-layers.swift Design/stickers/<名字>.png`（先用 `swiftc -O` 编译会快很多），它自动找到两只平涂的椭圆眼睛，并检查 base + eyes_open 与原图一致；现在七张角色贴图都已生成（知识库的眼睛是近黑色，加 `--dark-eyes`）。

有了分层，贴图每 2.5–6 秒眨一次眼（偶尔连眨两下，每张贴图节奏不同）；没人理它时隔几秒看向别处再回来；鼠标在窗口里时眼睛跟着鼠标走，头也朝那边歪一点。干活时往下看，出错时垂眼看向一侧，离线时闭眼睡觉。互动有三种：点一下（poke）先压扁再跳起、冒出小爱心和星星；鼠标移上去（greet）朝鼠标轻轻一跳；Bot 刚说了话（talk）连点三下头。Mac App 里只有 Bot 页头部的大贴图是全套动画（窗口在后台时停下不动）；侧栏头像只在鼠标移上去时眨眼、转眼珠，聊天气泡和设置里的头像是静止的（Mac 上列表行里的动画每一帧都会让整个列表重新排版，很费电）。打开「减弱动态效果」后，以上全部关闭，只显示状态的静止姿势。

## 5. 导出规格

贴图只需要一张大图，App 运行时缩放。下表是各处的显示尺寸：

| 位置 | 显示尺寸 | 说明 |
| --- | --- | --- |
| Mac 插件页卡片 | 约 120 pt | 大图，带动画 |
| Mac Agent 状态页 | 约 160 pt | App 自己的贴图，表情和动作跟着状态变 |
| Mac 菜单栏 | 18 pt | 缩小的全彩贴图；太小看不清细节，所以贴图的轮廓要清楚 |
| iPhone 今日页头部 | 72–96 pt | |
| iPhone 列表、待办来源 | 24–32 pt | |
| 手表 App 内 | 36–40 pt | |
| 手表表盘复杂功能、小组件 | 约 50 pt | 不能播放动画；表盘大多会染成单色，以后单独导出剪影版 |
| App 图标（iPhone、手表、Mac） | 1024 × 1024 | **只能是静态图**，见下文 |

关于 App 图标：

- **iPhone 桌面上的 App 图标只能是静态图**：系统只接受一张不透明的 1024 × 1024 PNG，不能动画、不能分层、不能透明；`setAlternateIconName` 换的备用图标也同样是静态图。
- iOS 18 起可以再提供深色版和着色版（tinted，系统会把它染成单色）。
- 建议用 App 自己的贴图（现在是 `lily_veil`）加一个浅色纯色背景（比如 `#EFE8FB`），不要放文字；手表图标会被裁成圆形，角色放在中间 80% 的圆里。

## 6. 给 GPT 的出图提示词

**用法**：把现有的一张贴图（`lily_veil.png` 或 `red_ribbon.png`）作为**画风参考图**一起上传，再用下面的模板。只参考画风（线条粗细、上色方式、头身比例、探头姿势），角色本身按描述画新的。

### 通用模板

> 画一张 Q 版大头贴纸，一个从画面底部探出脑袋的小角色：**〈角色描述〉**。和参考图保持完全一样的画风：深紫灰色（#302840）粗描边，外轮廓粗、内部线细；平涂上色，最多一层阴影，一两处白色高光；大眼睛，粉色腮红，没有身体。正方形 1024×1024 画布，透明背景，不要白底、不要投影、不要文字。角色水平居中，下方贴边，左右和上方留一点空白。不要出现任何应用的官方 logo。

### 角色描述示例（以后的插件，可以随意改）

- **飞书**：青蓝色短发、齐刘海，耳边别着一枚纸飞机形状的发夹，眼睛是浅青色，表情认真。
- **微信**：草绿色双马尾，头上别一个圆角方形的对话气泡发卡（只有一个气泡，里面两条横线），眼睛是深绿色，笑眯眯的。
- **短信**：橙色波波头，耳朵上挂着一个小小的手机挂坠。
- **邮箱**：玫粉色长卷发，头发上插着一个信封形状的发饰。
- **照片**：亮橙色短马尾，额头上推着一副相机造型的小墨镜。

### 出图后检查

- 背景是不是真的透明（在深色和浅色背景上各看一次）。
- 缩到 32 pt 时还能不能认出是谁（轮廓够不够清楚）。
- 和已有贴图放在一起，描边粗细和颜色是否一致。

## 7. 专属动画

六个角色各有四段代码绘制的动画，没有新增位图。`MascotAnimation.swift` 管角色目录、时间和选择；`MascotView.swift` 接入页面、时间线和预览按钮，原有图片缓存和分层绘制整理到 `MascotArtwork.swift`；`MascotAnimationView.swift` 用 SwiftUI Canvas 绘制道具，深紫灰 `#302840` 描边、角色强调色、平涂。画布和线宽一起按比例缩放；原贴图按透明边界放进完整方形舞台，为上方、侧边和下方的道具留位置。

| Bot | 四段动画（预览文件名） | working | done |
| --- | --- | --- | --- |
| 健康 | 蕾丝被子 `sleep`、怦怦心跳 `heartbeat`、早安伸懒腰 `stretch`、训练完成 `training` | 心跳与心电线 | 举哑铃、星星庆祝 |
| 用量 | 算 Token `tokens`、额度仪表 `quota`、星空闪烁 `stars`、攒下星币 `savings` | 滚动数字和算盘珠 | 星币升起 |
| 成绩 | 红笔批卷 `grading`、蝴蝶结弹跳 `ribbon`、展示成绩单 `report`、学分勋章 `medal` | 勾卷子、写 A+ | 勋章和星星 |
| 作业 | 写作业 `writing`、叠好课本 `books`、上课铃响 `alarm`、晶石光环 `halo` | 铅笔逐行写字 | 课本依次叠起 |
| 校园 | 翻日历 `calendar`、请假已批准 `approval`、帽上流星 `meteor`、月亮轻摇 `earrings` | 日历翻页 | 请假条盖章 |
| 助理 | 撑伞提醒 `umbrella`、勾好待办 `checklist`、挥手你好 `wave`、月牙发光 `moon` | 清单逐条打勾 | 挥手、爱心 |

### 播放规则

- 只有 iPhone、Mac 的 Bot 页头部和「贴图预览」的角色大图显式开启 `characterAnimations: true`。默认关闭，侧栏、列表、聊天、菜单栏、手表、小组件都不会意外播放。watchOS 不编译道具绘制部分。
- `working` 循环工作动作；`done` 播一次表中的庆祝动作。状态切换立即中断旧动作；错误保留原来的汗滴和静止/基础状态表现。
- 白天 `idle` 首次等待 20–40 秒，再从该角色的待机动作里挑一段；相邻动作的开始时间间隔随机为 20–40 秒，不连续重复，也不让健康白天自动盖被子。随机数发生器可注入种子，测试不依赖真实等待。
- `poke` 随机选择该角色四段中的一段，避免连续重复，代替通用跳跃和爱心爆发。预览按钮指定动画，点击可重新播放；这两类请求都优先于当前自动动作，结束后恢复状态动作。
- 健康 `offline` 和设备本地时间 23:00（含）至 6:00（不含）的 `idle` 持续盖被子睡觉；被子只在进入时拉起，随后随呼吸起伏，眼睛闭合、Zzz 飘动。其他角色离线沿用原来的 zzz。
- 睡觉闭眼，伸懒腰眯眼打哈欠，批卷、写字、算数和清单动作往下看。头部动作与眼睛仍用现有分层素材。
- App 不活跃或 Mac 窗口在后台时不创建动画时间线；恢复时重新安排自动动作，避免补播离开期间的待机动作。打开「减弱动态效果」后不播道具、眨眼和互动，只画原有状态的静止姿势，预览按钮禁用。
- 时间线留在 `MascotView` 内，30 fps；动画时钟不发布逐帧状态给页面，避免每帧刷新外层列表。

### 给新 Bot 加动画

1. 在 `MascotAnimation` 加枚举值，填写 `sticker`、中文 `title`、`accent`、`duration`；为新角色指定 `working(for:)` 和 `celebration(for:)`，必要时调整 `idle(for:)`。
2. 在 `MascotPropPainter.draw(in:)` 增加对应绘制函数。坐标采用 240 单位画布，固定道具放在完整舞台内；头饰用 `placement.point(x,y)` 把原贴图的 0–1 坐标映射到舞台，并在 `attached` 中注册，以便随头转动。
3. 眼睛或姿势的特殊变化放进 `MascotAnimationPlayback.applying(to:)`；不在 View 里增加计时器或后台任务。睡眠时间等选择条件放在可测试的 `MascotAnimationPlayer`。
4. 添加核心测试，运行 `swift test`、三平台构建和导出脚本，检查整组预览。预览页和导出脚本按枚举自动列出新动画，无须单独接按钮。新角色不声明动画时保留旧行为。
