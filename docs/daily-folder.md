# 每日文件夹

每天一个文件夹，把这一天的课、消息、待办和各个 Bot 负责的事放在一起，给你看，也给 Agent 读。实现在 `backend/core/daily.py`。

## 在哪里

长期记忆（Obsidian 目录）里的 `每日/<日期>/`，默认是 `backend/.state/vault/每日/2026-10-25/`。数据目录不进 Git；可以用 Obsidian 或访达直接打开。写入时同时更新搜索索引，所以 Agent 用 `memory_search`、`memory_read` 就能找到。

## 里面有什么

| 文件 | 内容 | 负责 |
| --- | --- | --- |
| 今天.md | 分工：每个 Bot 负责哪个文件、这一天有几件事；这一天各来源的摘要 | 助理Bot |
| 消息.md | 白名单会话这一天读到的消息，按来源和会话分组；只有识别出的文字，不含截图；@全体成员 和只来自预览的会标出来 | 消息来源 |
| 待办.md | 今天截止、已经逾期、今天新记下的、今天完成的待办，带截止时间和来源；数据看门狗还没好的提醒单列在最后的「系统提醒」，不算待办 | 助理Bot |
| 作业.md | 今天要交、逾期、今天交完、今天新布置、之后一周要交的作业，带课程 | 作业Bot（homework） |
| 活动与请假.md | 今天的活动、今天报名截止的、今天的请假、之后一周的活动 | 校园Bot（campus） |
| 成绩.md | 这一天出的成绩，已修学分和平均绩点 | 成绩Bot（grades） |
| 健康.md | 准备度、昨晚睡眠（总睡眠，有小睡时分开写主睡眠和小睡）、预警、晨间简报 | 健康Bot（health） |
| 天气.md | 这一天的天气、带不带伞、穿什么，和早上的今日提醒（见 [weather.md](weather.md)） | 助理Bot（weather） |
| 本周回顾.md | 写好当天的回顾与周报链接，今天.md 提一句；周报在 `周报/<ISO年>-W<周>.md`，见 [weekly-review.md](weekly-review.md) | 助理Bot（weekly_review） |
| 课程.md | 这一天的课和自己加的日程，起止时间；页面还没显示过的那一周按最近读到的一周推测，并注明（见 [timetable.md](timetable.md)） | 作业Bot（timetable） |

插件停用时它的文件不再更新，已经写好的留着。

## 什么时候更新

- 数据库是记录，文件是从它整理出来的：任务 `daily_notes` 每 10 分钟重写今天和昨天的文件夹，每次提炼待办之后也马上重写今天的。
- 内容没变的文件不会重写，所以 Obsidian 和搜索索引不会频繁变动。
- 每个文件最后有一节「## 笔记」：Bot 和你写在这里，重写时原样保留；上面的部分每次按数据库重写，在那里改的会被覆盖。

## Bot 怎么用

- 提炼待办时，Agent 先读当天的 `今天.md`，看已有的课、截止的事和分工，再把新消息里的事交给对应的 Bot：作业用 `homework_mark`，活动和请假用 `campus_event_add`、`campus_leave_record`，成绩用 `grades_record`，其余是助理Bot 的待办。一次提炼就分完，不用每个 Bot 各读一遍消息（每多一次 Agent 运行就多用一份额度）。
- 和某个 Bot 聊到某一天时，它先读那天的 `今天.md` 和归它的文件；它对这一天的分析和打算写进自己文件的「## 笔记」。

## 插件怎么加自己的文件

插件实现异步的 `daily(day)`，返回 `{"file": "作业.md", "bot": "作业Bot", "summary": "今天要交 1 项", "body": Markdown}`，没有内容时返回 `None`。`summary` 是 `今天.md` 分工里的那一行；文件名不能带路径，也不能和核心的三个文件重名。出错或超过 20 秒时记一条 `plugin:<id>:daily` 失败的运行记录，其他文件照常写。

## 隐私

截图和原始数据不离开 Mac；这些文件里只有识别出的文字，和提炼待办时发给模型的内容一样。备份会连同长期记忆一起备份这些文件。
