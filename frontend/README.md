## 本地运行（Mac）

```bash
brew install xcodegen
cd frontend
xcodegen generate          # 生成 Assistant.xcodeproj
open Assistant.xcodeproj
swift test --package-path Packages/AssistantCore
```

用免费的个人开发者账号装到真机：在 Xcode 每个 target 的 Signing & Capabilities 里选你的 Personal Team，并把 `project.yml` 里的 `BUNDLE_ID_PREFIX` 改成你自己的、唯一的前缀，然后重新运行 `xcodegen generate`。没有启用推送通知、iCloud 这类需要付费会员的能力；iPhone、手表 App 和各自的小组件共用 App Group（见下文）。免费账号签的 App 7 天后需要重新安装。

**iPhone 和手表一起装**：手表 App 嵌在 iPhone App 里（`Assistant-iOS.app/Watch/`），在 Xcode 里选 `Assistant-iOS` scheme 装到 iPhone，手表 App 和表盘小组件会跟着装到配对的手表上，不用再单独装。如果手表上没出现，打开 iPhone 上的「Watch」App：「通用」里打开「自动安装 App」，或者在「我的手表」页面底部的「可安装的 App」里点「安装」。`Assistant-watchOS` scheme 仍然保留，开发时可以直接装到手表上调试。六个 target（iPhone、iPhone 小组件、分享扩展、手表、手表小组件、Mac）都要选同一个 Personal Team；免费账号每 7 天最多注册 10 个 App ID，这个项目一共用 6 个 App ID（iPhone、iPhone 小组件、分享扩展、手表、手表小组件、Mac），分享扩展新增 `<前缀>.ios.share`。

## 分享扩展

在其他 App 里选中文字，或打开网页的分享菜单，选「转给助理」。`Assistant-share` 随 iPhone App 安装，标识为 `<前缀>.ios.share`；首次可能要在系统分享菜单的「更多」里启用。支持文字、HTTP/HTTPS 网页链接及来源 App 提供的页面标题；**不接受图片、文件或混合了图片/文件的分享**。图片文字识别仍在 Mac 上完成，这次不做。来源 App 没有开放系统分享时，请复制文字后用主 App 的「贴一段消息」。

扩展使用独立 SwiftUI 页面：可编辑原文、加最多 500 字备注、从主 App 缓存的屏幕读取白名单选会话、标记「这是助手漏掉的」。原文超过 8000 字会提示并截断；长度按后端的 Unicode 码点计算。会话只读本地缓存，不为名单联网；首次安装或白名单刚改过，请先让主 App 成功刷新。iOS 不可靠地提供来源 App 身份，未选会话时不猜测来源；选会话时才附对应 QQ/微信来源。

主 App 启动和保存连接设置时将后端地址、模拟模式写入 `group.<前缀>`，成功读取插件后缓存白名单。令牌始终在钥匙串：iPhone 和扩展共用 `$(AppIdentifierPrefix)<前缀>.share-token`；主 App 启动时把原有 `local.assistant.api` / `bearer-token` 项复制过去，仍保留原项，读取优先原项、再读共享项。保存新令牌同时更新两处。扩展只读共享项，令牌不进 App Group 的 UserDefaults、文件或队列，小组件也没有共享钥匙串权限。

扩展直接请求 `POST /api/v1/inbox`，请求和总时长均限 10 秒。开始发送前先保存到 App Group；成功显示「已转给助理」并自动关闭。连不上 Mac、令牌读不到、超时或服务器拒绝时，保留内容并显示「已存下，连上 Mac 后会发出去」。主 App 成功刷新后每次最多补发 5 条；系统后台刷新与 HealthKit 唤醒的刷新也会尝试补发，仍受原有 20 秒总预算限制；每条只有收到成功响应后才转为已发送，失败即停、下次重试。App 和扩展通过文件锁与 60 秒发送租约协调；本地待发送的相同原文合并，后端还会对同段原文做 10 分钟幂等。已发送记录不会再次发送；主 App 导入 `ManualEntryStore` 并写入聊天后才清理共享记录。成功补发后，助理聊天会显示和「贴一段消息」一样的转发记录；仍有未发送的条目时，助理页面显示数量。

若后端已收下但响应丢失，且超过 10 分钟才重试，当前接口仍可能产生重复；要彻底消除这个窗口需要后端支持持久的请求标识，本次遵守接口约定未改后端。

队列按提交时的后端地址隔离：改连接不会把旧内容发给新的 Mac，切回原地址后继续。模拟模式不联网、不新增队列，也不补发真实队列，已有真实内容保留。缺少 App Group 权限或本地存储损坏时不会假装保存成功，也不会用私有目录代替共享目录。

**免费个人账号签名**：在新增的 `Assistant-share` 和其余五个 target 都选同一个 Personal Team，修改唯一的 `BUNDLE_ID_PREFIX` 后重新 `xcodegen generate`。iPhone 和分享扩展的 App Group 必须一致；两者的 Keychain Sharing 都要包含上面的共享组。保留 iPhone entitlement 里第一项私有组，以便读取升级前的令牌。`AppIdentifierPrefix` 由签名展开，勿直接写死 Team ID；换 Team 或前缀后请在主 App 重新填写令牌。Apple 当前的[能力表](https://developer.apple.com/help/account/reference/supported-capabilities-ios)将 Keychain Sharing 和 App Groups 都列为免费 Apple Developer 可用，但具体设备仍要验证 provisioning profile。若共享钥匙串被拒绝，绝不能把令牌放到共享文件中：可移除两处共享钥匙串 entitlement 与 `AssistantSharedKeychainGroup`（保留 iPhone 私有组），扩展将只入队，由主 App 发送。App Group 则是队列必需能力，不能移除后仍期待转发工作。免费账号的 App ID 和签名周期限制仍适用，共计 6 个 ID。

真机验收建议覆盖：Safari 标题加链接、QQ/微信文字、超过字数限制、断网后重新打开主 App 补发、重复点击发送、主 App 和扩展同时运行、切换模拟模式、修改地址后切回、从旧版升级后的令牌迁移。未经真机签名与分享菜单测试，不能仅凭关闭签名构建认定共享钥匙串授权已验证。

## AssistantCore

- **模型**：`docs/api.md` v1 的全部数据结构（Todo、Today、Status、Digest、Run、PluginView、RuntimeSettings、HealthBatch…），字段名通过 CodingKeys 对应接口的 snake_case；时间支持后端的微秒精度。
- **APIClient**：每个 HTTP 接口一个 async 方法；Bearer Token 由 `TokenProvider` 提供，App 里用 `KeychainTokenStore`（本机钥匙串的通用密码项，`AfterFirstUnlockThisDeviceOnly`，不同步到 iCloud）；错误映射为 `APIError`（401/403/404/409/422/5xx、缺 token、解码失败）。每台设备用自己的设备令牌（iPhone、Mac App 各一个，`app` 权限），在 Mac 上用 `uv run python -m scripts.tokens create <名称> --scope app` 创建，见 [api.md](../docs/api.md)「连接与鉴权」；令牌没有 `app` 权限时 App 显示「这个令牌没有使用 App 的权限」。
- **卡片**：`Card.content` 把 `{type, title, data}` 解析成 `list / stat / chart / photo_grid / text / todo_list`；不认识的类型或字段不全时返回 `.unsupported`，不会让整个今日页解析失败。字段约定见 api.md 的「卡片 data 约定」。
- **DueText**：截止时间的显示（「今天 17:00」「明天」「已逾期 · 10月14日」）。
- **插件贴图**：每个插件一张贴图，放在 `Design/stickers/`，整个文件夹打包进三端 App；插件在 manifest 的 `mascot.sticker` 里选用哪张，没有贴图时显示占位图，App 自己用哪张写在 `Design/stickers/app.json`。`Mascot.swift` 是纯逻辑（贴图选择、API 状态到五种状态的映射、状态机、每一帧的位移/缩放/歪头），有单元测试；`AssistantUI/MascotView.swift` 负责绘制和动画，开启「减弱动态效果」时只显示静止姿势。流程见 [docs/mascot.md](../docs/mascot.md)。Mac App 和 iPhone 的设置里的「贴图预览」能看到所有贴图在各状态下的样子。

## Mac App

左边是 Bot 列表，右边是选中的 Bot，像聊天软件；菜单栏另有一个小图标。

- **Bot 列表**：最上面一行是「仪表盘」；有收藏时「收藏」排在「助手」上方。助理Bot 管理个人待办和每日总结，角色插件各有自己的 Bot（见 [mascot.md](../docs/mascot.md)），知识库Bot 管理知识库、GoodNotes、课堂照片和视频。每组都可按用户顺序排列，消息来源单独列在下面。长按或右键 Bot 行能收藏、重命名、排序和选择是否在仪表盘显示。头像是贴图里角色的脸，右下角的小圆点只在需要注意时出现（忙是蓝色、出错红色、离线或停用灰色，正常不显示）；名字优先用本机自定义名，默认是贴图对应的角色名（`Design/stickers/characters.json`），没写就用插件名，右边是它最近说话的时间；名字下面是它最近说的一句话（还没说过话时是它管什么，如「学分 · 成绩」），有没看过的新消息时名字加粗、右边一个蓝色小圆点（每个 Bot 都是同一种蓝）。最下面是连接状态和「设置」。
- **设置里的「仪表盘」**列出每个 Bot 的头像、显示名和开关，也能拖动排序。「恢复默认」重置顺序、显示和收藏，保留改名。偏好存在本机 UserDefaults，各设备独立设置，聊天请求沿用 Bot 原名。全部隐藏后，仪表盘的「去设置」可重新选择 Bot。
- **仪表盘**：所选 Bot 的卡片汇集在这一页（`DashboardPage`，部件在 `DashboardParts.swift`），Bot 页只剩聊天。这一页是编排过的，不是把每个插件的卡片依次摆出来：要你处理的事在最前面，没有内容的数字退到后面，一张卡片不重复旁边那张已经说过的（规则在 AssistantCore 的 `DashboardEdit`，有单元测试）。最上面是小字的日期和衬线体标题。助理Bot 开启显示时，下面是她的「今天」一组：今日待办在最前面也最宽，待办下面是今天的总结里「还不确定」的几条（橙色的一行「还有 N 条没看清，要你确认」，点开进入完整卡片栏，可逐条「读全文」「记成待办」「不用管」），宽屏时今天和明天的天气排在右边，iPhone 上在待办下面并排；紧邻的出门提醒省略天气卡已经显示的数字，仍保留带伞、穿衣建议和降雨时段。今日提醒在这里不再说第二遍：它的「待办」一节去掉（待办就是上面那张卡片），旁边有天气插件自己的卡片时「天气」一节也去掉，只留课程和其余注意事项，已经列在今日待办里的系统提醒只显示一次；什么都不剩时整张不显示（Bot 自己的卡片栏里仍然是全文）。「今天」下面是「一览」：有数字可看的 Bot 各一个小方块，需要注意的（红，然后橙）排在最前面，其余按下面各组的顺序；左上是它的脸和这个数字是什么（用它的颜色），下面是大数字、有进度时一条细条、再一行小字，需要注意时小字和细条变橙或红；点一下滚到它那一组；只有一张一览卡时，直接打开完整卡片栏。数字由 AssistantCore 的 `DashboardGlance` 从已有的卡片里挑，不加新接口：后端标了橙或红的那一行优先（如 Claude 本周已用 82%），其次是插件放在最前的大数字、正在上或下一节课、第一张数字卡片、第一个圆环（平均绩点 3.62 / 4）、圆环图的总数。助理Bot 的待办就在上面，这里没有她的方块。没有内容的 Bot（比如还没出成绩的成绩Bot）只出现在「没有新情况」一行，点头像打开聊天；还没连上 Mac 时每个 Bot 先各占一个灰色方块，免得这一排跳动。iPhone 上这一排左右滑（从这一排上横滑不会拉出 Bot 列表），Mac 和 iPad 上排成均匀的几行。再往下按所选顺序每个 Bot 一组，一览已经展示的卡片从面板中移除：一块圆角面板，头部铺一层它颜色的淡底，是它的脸、名字、管什么的小标签、最近说话的时间和它最近说的一句话（出错、离线时换成状态），右边「聊天 ›」打开它的页面；卡片在面板里排成格子，格子之间一条细线，边框只画在整组外面。Mac 和 iPad 每组先显示一行（一行放得下三张以上时；窄窗口两行），同一行顶部对齐，卡片按内容取高度，最后一行不满时铺满；iPhone 每组先显示前 2 张（并排的两张数字小卡片算一行，不拆开），「今天」全部显示；其余收进组底部的小字「还有 N 张卡片」，展开后是「收起」，本机记住。还没有内容的卡片（数字是「—」或 0、每个圆环都是空的、全是 0 的图）排在这个 Bot 其他卡片的后面，所以先被收起来的是它们。仪表盘上的列表在 iPhone 最多显示 3 项，Mac 和 iPad 最多 5 项，点「还有 N 项」可查看全部。资料来源只显示启用和停用数量，开关在知识库的完整卡片栏里。列表行右边的字是数字时和标题一样深（「344 元」「已用 88%」），是状态时是一个灰色小标签（「审批中」「还没报名」）。三种卡片风格照样生效（柔光时格子和边框带 Bot 的颜色）；方块和卡片在页面打开时依次淡入，开启「减弱动态效果」时直接出现。最底下一行是消息来源，一行是停用的 Bot，都是带图标、点了打开页面的小胶囊。卡片来自 `/api/v1/today`（每张带 `plugin`，一个请求就够）；旧后端没有 `plugin` 时退回每个插件各取一次。Mac 第一次打开、iPhone 启动或离开超过一小时回来时显示仪表盘，其余时候回到上次的页面。
- **Bot 页**：最上面是这个 Bot 的头部：一条 112 点高、它颜色的底色，角色从底边探出头（按眼睛位置统一大小），旁边是名字、管什么和一句话状态，说的是这个插件替你做了什么而不是它的任务（消息来源：「10 分钟前读过消息，记下 3 条待办」；角色：「4 分钟前更新过」，由 Agent 读消息时顺手记的学分成绩、请假这类还没有内容时是「还没有记录」）；连不上 Mac 时头部下面有一条横幅（数据是什么时候的、「重试」）。再下面是纸飞机波浪线和这个 Bot 说过的话，页面打开时直接停在最新一条（内容不满一屏时从顶上排起，头部在最上面，不再被压到窗口底部、上面空半屏；iOS 18、macOS 15 起）：Bot 的消息不加气泡、整宽排版（上面一行是小头像、名字和时间，几分钟内连着说的只显示一次），粗体小节、「- 」条目和 Markdown 表格按固定格式画出来（表格列宽跟着内容，五列以上放不下时左右滑动）；Bot 在回复里附的卡片或按参数现画的图（最多 2 张，比如「最近 30 晚睡眠」「最近 6 个月花销」，都是写回复那一刻的快照，见 api.md 的「插件的预设图」）画在文字下面，长图的横轴只均匀标 7 个左右的日期、最新一天总会标出，注明「截至几点」，「看最新」打开卡片栏；我发的在右边的气泡里；失败的运行是一行带警告图标的提示。聊天和输入框在居中的 760 点阅读列里。这个 Bot 的卡片在右侧的卡片栏（SwiftUI 的 inspector，工具栏的方格按钮显示或隐藏，本机记住），全部显示、不折叠。还没读到数据时待办和聊天显示灰色占位，没说过话的 Bot 给几个可以问的问题。开启「减弱动态效果」时这些动画都不播放。
  - **Aemeath Bot**：卡片（仪表盘的「今天」一组和页面的卡片栏）是天气插件的卡片和今日待办。待办每条两行：标题，下面一行是截止时间（逾期标红）和来源（哪个群、谁发的，鼠标停留显示原文），还没同步到提醒事项时才多一个小图标；在 Bot 卡片栏可以勾选完成、编辑（标题、备注、截止时间）、删除（会同时删除提醒事项）。标题行的「＋」可以自己记待办，也可以贴一段消息转给助理；编辑页的「原文」先显示片段，点「看完整原文」才读取引用的消息。Agent 在头部：状态行写「空闲 · 9 分钟前提炼过」，右边是「立即提炼」；某个 Agent 不可用时头部下面才出现提示（两个都不可用时是橙色警告）。头部的贴图表情和动作跟着 Agent 状态变。聊天里是今天的总结，以及正在进行或失败的提炼（各占一条）；顺利完成的提炼不再出现在聊天里（那是运行记录，不是她说的话，而且每完成一次都会点亮一次未读），上次什么时候提炼过看头部的状态行，每一次都在「运行记录」里。今天的总结是各消息来源当天的摘要，按「新待办 / 通知 / 还不确定」分节。每个 Bot 的聊天一打开只显示今天的，上面的按钮每点一次往前多看一天。工具栏按钮打开完整的运行记录表。
  - **角色 Bot 和消息来源**：卡片是后端返回的插件卡片（动态显示），停用时换成启用开关；聊天里每天一条：Agent 写的信息摘要和这天提炼出的待办。健康插件（健康Bot）的晨间简报和周报（失败的写明原因）也作为消息发出来，所以它的文字卡片不再重复显示，其余是指标卡片（见 [api.md](../docs/api.md) 的「health 插件的卡片」）。健康Bot 的卡片最后还有一张「今天的记录」，点「记录」弹出表单：手动记健身 App 的准备指数和自己的体感，用来校准准备度（见 [readiness-calibration.md](../docs/readiness-calibration.md)）；「健康预警」没有预警时不显示。多系列图表和环形图用一套低饱和的配色，睡眠分期用接近 Apple 健康的颜色。工具栏的 ⓘ 是启用开关和插件信息。
  - **输入框**：发给这个 Bot，Mac 上的 Agent 读了待办和记录后回答（`/api/v1/bots/{bot_id}/messages`，见 [api.md](../docs/api.md)）；回答期间头部角色显示在忙，可以继续输入，上一句回完前发送按钮暂不可用；忙碌提示显示已经等了多少秒。
- **设置**：第一页只有几行，每行点进去是单独一页（和 iPhone 同一套）：连接（模拟数据开关、后端地址、令牌存钥匙串）、插件（每个插件一页：开关、仅预览、白名单或课程群、插件信息）、消息来源、运行时间表（读取消息和提炼待办的 cron，附中文说明；置信度阈值；优先使用的 Agent）、运行记录（一张表）、对账（按周看抓到的待办、提前时间、晚发现和自己补的条目）、贴图预览。

菜单栏图标是 App 贴图在当前状态下的静止图（菜单栏不能播放动画）加今日剩余待办数；点开是一个小窗口：动画贴图、今日待办（可以直接勾选完成）、「添加待办或消息」「立即提炼一次」「打开主窗口」。

数据流：`AppStore`（AssistantUI）从 `Backend` 读数据并执行操作，每 30 秒刷新一次，有任务在运行时每 2 秒刷新一次。`Backend` 有两个实现：`LiveBackend`（经 `APIClient` 访问后端）和 `MockBackend`（内存里的示例数据，完成、编辑、删除、立即运行、开关插件、改时间表都能操作）。页面要显示的文字和分组（来源、同步状态、插件一句话状态、摘要分组、运行记录的中文、cron 说明、编辑表单只发送改动的字段、Bot 列表和每个 Bot 的消息 `Bots.swift`）都在 AssistantCore 里，有单元测试。

## 手动补记、转发和核对

这些入口由 Mac、iPhone、iPad 共用（`AssistantUI/Shared/`），使用 `Backend` 协议，真实后端和模拟数据都可操作：

- **添加**：助理卡片栏的「今日待办」标题右侧有「＋」；Mac 菜单栏小窗口也有「添加待办或消息」。新建页可切换「新建待办」「贴一段消息」，iPhone 上先打开半屏页，Mac 上打开 sheet。手动待办支持备注、日期或具体时间；可标「这是助手漏掉的」，来源会话从 QQ、微信等屏幕读取插件的白名单选择，也可以不指定。保存调用 `POST /api/v1/todos`；200 表示重复，显示「已经有这条了」并打开返回的那条待办；201 是新建成功，页面直接关闭。新待办如果不在今天（截止时间在以后，或者没有截止时间），会出现在「今日待办」卡片下面的「之后的 N 件」里：这一栏列出所有还没完成、又不在今天列表里的待办，最近到期的在前，没有日期的在后，平时收成一行「之后还有 N 件」，展开状态本机记住，刚新建完会自动展开。来源一行里，自己记的只写「我自己记的」，转发的写「我转给助手的」加你选的会话，不再带后端归档用的「手动新建 · 我」。
- **转给助理**：「贴一段消息」支持最多 8000 字原文、500 字备注及可选会话，iPhone 可用系统粘贴按钮。调用 `POST /api/v1/inbox` 后，在助理聊天里保存一条「我」的转发记录（正文显示前 300 字），等待提炼期间显示正在忙和等待时长。聊天记录保存在提交设备本机，并按模拟/真实后端地址隔离；接口目前没有跨设备聊天记录和单条消息的处理状态，忙碌状态根据提炼运行记录更新，15 分钟没有结果会提示去总结和运行记录查看。
- **还不确定**：今日待办卡片下面可展开逐条处理；助理「今天的总结」的「还不确定」一节也有相同动作。「读全文」只在后端允许时出现，调用 `POST /api/v1/plugins/{id}/open-chat` 后显示「正在读…」；次数用完、白名单变动、未允许点开都有中文提示。「记成待办」预填该行文字。「不用管」只在本机隐藏当天这一条，刷新、重开页面和重启后仍生效，次日自动失效。优先使用 `Today.unsure`；旧后端缺字段时解析摘要，仍可补记和隐藏，但不提供读全文。
- **聊天待办**：每个 Bot 每天的「提炼出的待办」和助理总结下面「今天新建的待办」都使用与今日卡片相同的行，可勾选、点标题编辑、长按或右键打开菜单；各处共享当前状态。删除助手生成的待办会询问原因（不是待办、已经做了、重复了、时间不对），也可直接删除；自己新建的直接删除。原因通过 `TodoPatch.reason` 提交，旧后端返回 422 时去掉原因重试一次。
- **原文**：待办编辑页保留来源和原文片段；点「看完整原文」才请求 `GET /api/v1/todos/{id}/sources`，逐条显示来源、会话、发送人、时间和识别文字，不读取或展示截图。没有片段、引用已不可用、后端尚未更新时均有说明；Mac 待办行的悬停原文提示保留。
- **对账**：设置 → 对账，请求 `GET /api/v1/stats/extraction?weeks=4`；顶部用一句话说明最新一周，下面每周一行（不是多列表格，手机上放不下六列）：左边是「这周（11月9日起）」，右边是「抓到 N 条」，第二行只写有的内容：提前多久（中位数）、晚了几条、你补了几条、几条不是待办、抓到的比例。空周写「这周没有数据」。「我转给助手的」对应 `share`，「我自己记的」对应 `app`，来源、摘要和原文使用同一套名字。

新路由在旧后端返回 404 时，在当前页面提示「Mac 上的后端还没更新」，不影响其他页面。新接口的线格式在 `AssistantCore/ManualEntry.swift`、`ExtractionStats.swift`；模拟后端支持手动新建去重、转发幂等及模拟提炼、点开会话、原文与对账。新增路由、兼容回退、输入边界、跨页面状态和本机恢复由单元测试覆盖。

## iPhone App

按手绘草图做，和 Mac 一样以 Bot 为中心：

- **主屏是仪表盘或一个 Bot 的页面**：仪表盘和 Mac 是同一页（单列，「今天」在最前面，「一览」左右滑，每个 Bot 先显示 2 张卡片），左上角打开 Bot 列表，列表最上面一行就是仪表盘。Bot 的页面最上面是紧凑的一行头部：左边是它的脸，在一个 64 点、它颜色的圆里（会眨眼，点一下有反应，Bot 说话时点头），右边是名字、一个标签写它管什么（每个 Bot 一样的格式：「学分 · 成绩」「作业 · 课表」）和一句话状态，助理Bot 最右边是「立即提炼」；头部滚出屏幕后导航栏中间才显示小头像和名字。然后是带纸飞机的波浪线和它说过的话（`ChatTimeline`，和 Mac 共用，打开时停在最新一条），最下面是输入框（消息来源没有）。右上角的方格按钮从下面弹出这个 Bot 的卡片（半屏，可以拉到全屏，和 Mac 用同一套 `BotCards`）。卡片标题 17 点宋体，正文 15 点，小字 13 点。下拉刷新。助理Bot 是个人助理，她的卡片是天气插件的卡片（今日提醒、今天的天气、出门要不要带伞和穿什么、明天，见 [weather.md](../docs/weather.md)），然后是今日待办：点圆圈完成，点一下待办编辑（半屏弹出页，导航栏里有「取消」「保存」），长按有完成、编辑、删除。页面顶上是左上角打开 Bot 列表的按钮和右上角的卡片按钮；插件开关、插件信息和运行记录都在设置里。
- **输入框**：像 Claude 的 App，空着时是一行圆角输入框：左边是选模型的按钮（「✦ 自动 ⌄」），中间是文字，右边是发送；文字多了往上长高，页面在它后面渐隐。连不上 Mac 时不能发送，占位文字会说明。可以选「自动」（按设置里的 Agent 顺序），或者 Claude Code 的 Fable、Opus、Sonnet，或者 Codex、DeepSeek 列出来的模型；选的这个 Agent 先回答，失败时照常换另一个。选择记在这台设备上，Mac App 的输入框也一样。
- **Bot 列表从左边滑出**：在页面上向右滑，或者点左上角的按钮，页面往右让开，露出助理Bot 和角色 Bot（每个一行，圆形头像、名字、管什么，有新消息时加粗带圆点），管知识库的知识库Bot 也可收藏和排序；左下角是设置齿轮和连接状态。点一个 Bot 就换过去，向左滑或点右边露出的页面就收回去。App 下次打开时回到上次看的 Bot。消息来源（QQ、飞书、微信）不在这里，免得误点，在设置的「消息来源」里。
- **设置**：齿轮打开，第一页只有几行，每行点进去是单独一页：连接（后端地址、令牌、模拟数据）、插件（每个插件一页：启用开关、QQ 和微信的仅预览、白名单或课程群、插件信息）、消息来源（点一个就关掉设置、打开它读到的消息）、运行时间表、运行记录、对账、贴图预览。Mac App 的设置是同一套两级页面（`Shared/SettingsPages.swift`），在窗口里一页页点进去；运行记录在 Mac 上是一张表。
- 颜色和字体和 Mac 一样，仿 Claude 的 App：米色的列表、更浅的页面、白色卡片，标题用系统衬线体；深色模式下换成对应的深色。

## 通知

iPhone 的「设置 → 通知」有四个独立开关：早上的简报、有条目要你确认、有人问你问题（前三项默认开），以及明早出门提醒（默认关，默认时间 7:30）。默认开关只表示偏好：首次在通知页点「允许通知」，或第一次开启某一类时才申请系统权限；启动、后台刷新和健康数据唤醒均不会弹出通知授权。拒绝后页面保留偏好，并提供系统设置入口。不使用远程推送，不重复提醒待办到期，也不为后台任务失败发通知。

- 健康的晨间简报和助理的今日提醒每天各最多一条；「还不确定」只提醒今天新出现的条目。成功提交的标识存本机，重开 App 或内容重新排序不会再提醒。
- 每个 Bot 最新、当天、已写好的消息带快捷回复时才提醒。长按展开通知可见最多四个回复按钮，不打开 App 直接走现有聊天接口。发送前再次核对最新问题，已回答、跨日或被新消息替代时不会发送；按钮不自动重试，避免网络超时后重复发送。未确认送达时，通知设置页会显示说明，请打开聊天核对。
- 天气插件「明天」卡片里的温度、伞和穿衣建议会提前排到次日的本地时间；重新取得预报时更新同一条定时通知。不会把今天的「出门提醒」冒充明天的建议；卡片没提供的建议不自行编造。关闭开关会取消相应的待发通知。
- 点简报或确认通知打开仪表盘，点问题打开对应 Bot。`aemeath://open` 和 `aemeath://open?bot=<id>` 供通知和小组件共用，合并到其他 Bot 的插件会打开所属 Bot 页面。

每次界面刷新会更新小组件快照，并最多每 30 秒补读所有 Bot（包括从未打开的聊天）。回到前台、系统后台刷新 `BGAppRefreshTask`、HealthKit 的后台数据唤醒也走相同的短刷新流程：今日概览、插件列表、健康简报和各 Bot 最新消息；最多四个聊天请求并行，总刷新预算 20 秒，系统到期会取消网络任务并恰好结束一次。后台刷新排下一次最早 30 分钟以后，实际唤醒时间由 iOS 决定，不能保证简报一生成就通知。模拟数据不会发通知，避免虚构提醒。

核心规则、偏好、去重记录、刷新取数和页面链接在 AssistantCore 的 `PhoneReach.swift`、`ReachRefresh.swift`；系统权限、本地通知、后台任务和按钮处理在 `AssistantUI/Phone/PhoneReach.swift`。无需新增后端接口、推送证书或 App ID。

## iPhone 小组件

新增 `Assistant-phoneWidget`，一个 WidgetKit 扩展同时提供桌面小号、中号，以及锁屏圆形、矩形。桌面小号和锁屏矩形显示「此刻」最该看的事（复用手表 `WatchSnapshot.moment`，随上下课和待办截止时间变化）；桌面底部是今天剩余待办数。中号右侧显示今天前三条未完成待办，逾期标红；锁屏圆形只显示剩余数。点按打开仪表盘或所属 Bot，锁屏内容标为隐私敏感，遵循系统隐藏设置。

iPhone 每次刷新后把精简的 `WatchSnapshot` 写入 App Group `group.<前缀>` 的独立键 `phone.widget.snapshot`，扩展只读这份快照，不联网、不读取令牌。复用手表的卡片解析、优先级和时间线变化点；财务卡片不写入快照。跨日或超过一天的快照显示数据时间和「打开 App 更新」，不把旧待办计成今天。尚无快照时显示打开 App 的提示。后台不可用时，已经写入的快照仍能按本地时间换内容，系统决定实际刷新频率。

安装后打开一次 iPhone App 刷新，再从主屏或锁屏编辑页添加「此刻与待办」。iPhone 和新扩展都要启用相同的 App Group；手表上原来的两个 target 同样保留此分组。若 Personal Team 无法配置 App Group，需要在 Xcode 检查签名支持；不能共享时小组件显示无数据，主 App 仍可用。新的扩展随 iPhone App 嵌入 `PlugIns/Assistant-phoneWidget.appex`；原有手表仍在 `Watch/`。

## iPad App

iPhone target 是通用 App，同一份安装包支持 iPhone 和 iPad。iPhone 仍只竖屏；iPad 支持四个方向、分屏和 Slide Over。

- **宽屏**（`horizontalSizeClass == .regular`）：`PadRootView` 用系统的 `NavigationSplitView`。左边依次是仪表盘、「收藏」「助手」和「消息来源」，最下面是连接状态和设置。沿用 iPhone 列表的圆形头像、状态圆点、未读加粗和圆点，第二行显示 Bot 最近说的话，没有消息时显示它管什么。横屏默认显示侧栏，竖屏可用左上角的系统按钮展开或收起。
- **右侧详情**：仪表盘，或头部角色、纸飞机分隔线、聊天和输入框，这个 Bot 的卡片在右边的卡片栏（工具栏按钮显示或隐藏，本机记住）；卡片、聊天和动画复用共享组件。`CardGrid` 按详情栏可用宽度自动排多列（卡片至少 270 点宽，常见竖屏约两列、横屏约三列）；助理Bot 的今日待办、知识库Bot 的知识库入口不进网格，和 Mac 一样按固定顺序各占一行。设置、插件、运行记录和知识库都在右侧一页页打开。卡片栏、选择 Bot、打开设置均可直接触控，动画尊重「减弱动态效果」。接键盘时沿用输入框的 Return 发送，`⌘R` 刷新，`⌘,` 打开设置。
- **窄屏**（分屏、Slide Over 的 `compact` 宽度）：直接用 `PhoneRootView`，保留 iPhone 的抽屉和单列卡片。iPad 两种布局共用本机 `assistant.pad.bot` 选择记录，iPhone 仍用自己的记录。
- **健康和手表**：iPad 可以查看后端的健康卡片和简报，但不请求 HealthKit 权限、不启动健康上传，设置中也没有「健康数据」页；上传只由 iPhone 负责。iPad 不启动 `PhoneWatchBridge`，不和手表配对。令牌仍是每台设备各自保存在钥匙串里的设备令牌。

iPad 专用容器在 `AssistantUI/Pad/`；选择恢复、侧栏预览文字在 AssistantCore 的 `PadPresentation.swift`，网格列数在 `CardPacking.swift`，均有单元测试。`PadRootView` 的 Preview 明确使用 `MockBackend`，本地检查无需连接真实后端。

## Apple Watch

三端分工：Mac 是完整工作台，iPhone 是仪表盘和跟 Bot 聊天，**手表只管抬腕几秒钟的事**：现在该干什么、接下来是什么、我今天状态如何，并能一下勾掉待办。卡片、聊天和设置都留在另外两端。

### 四页

手表 App 上下翻四页（转数码表冠或手指上下滑），纯黑背景上每页只有一个 Bot 的颜色：

- **此刻**：把这一刻最重要的一件事讲清楚，一屏放下、不用滚动。上面是标题和时间，中间是大数字（还有 52 分钟），Bot 坐在一根进度线上，线走到头就是这件事结束的时候；下面是接下来的一两件事和天气（19:00 后是明天的天气）。选什么由 AssistantCore 的 `WatchSnapshot.moment(at:calendar:)` 决定，顺序是：一小时内截止的待办 → 正在上的课 → 半小时内要上的课 → 早上 5–10 点今天的准备度 → 三小时内截止的待办 → 已逾期的 → 今天其他有时间的截止 → 没有时间的待办 → 今天晚些的课 → 18 点后明天第一节课 → 今天没有安排（显示天气）。能马上动手的待办排在几小时后的课前面，课留在下面一行。「自己的日程」不说上课下课。
- 如果此刻的主角是待办，右边是一个大圆按钮，点一下或**双指互点**（watchOS 11 起，`handGestureShortcut(.primaryAction)`）就勾掉，手表震一下，出现 3.5 秒「做完了 · 撤销」，然后换下一件事。点标题打开对应的页，点下面的「接下来」也能跳过去；点 Bot 它会跳一下。
- **待办**：最上面是还剩几件和逾期几件，下面一根分段的线，每勾掉一件亮一段。列表里逾期的排最前，然后按截止时间；点一行就勾选或取消，双指互点勾掉第一件没做的。勾掉的留在原位变淡，不会从手指下面跑开，当天都留在列表里。底部是「让 iPhone 刷新」和更新时间；iPhone 不在附近时写明勾选的会等连上后同步。
- **课表**：今天的课按时间排在一条竖线上，上完的变淡，正在上的（或下一节）变大，带剩余时间和进度；打开时自动滚到这一节。最后一节课结束后换成明天的课（`coursePage`）。学校网站还没显示这一周、按上周推测的会写出来；课表插件没开或还没读到时说明原因。
- **状态**：健康Bot 的今日准备度画成满分 10 的圆环（打开时转上去），下面是一句话、比昨天的变化、各项分数的短条，再下面是昨晚睡眠（入睡到醒来）。数据不足时显示原因。

手表离开手腕、进入息屏时（`isLuminanceReduced`）背景全黑，隐藏 Bot 和按钮，只留标题和数字。待办标题标了 `privacySensitive`，会跟随系统隐藏敏感内容的设置。

标题用系统字体（SF + 苹方）：手表上没有宋体，也没法像 iPhone 那样下载，只用衬线的话英文和中文对不上；数字用 SF 圆体，和贴图的圆润感一致。

### 数据

手表**不直接连后端，也不需要令牌**：watchOS 上没有 Tailscale，离开家里的网络就连不上 Mac，所以数据都经过 iPhone。

- iPhone 每次刷新后，用 WatchConnectivity 的 `updateApplicationContext` 把一份小快照发给手表：今日待办（标题、截止时间、是否逾期、来源、是否完成）、剩余件数、Agent 状态、iPhone 是否连得上 Mac；还有从 `/api/v1/today` 的插件卡片里取出的「今天的课」「明天的课」（课表）、「今日准备度」和「昨晚睡眠」（健康）、天气，以及这些插件的贴图。手表离开 iPhone 时只会收到最新的一份。新字段都是可选的，旧版本 App 发来的快照照样能读。
- **财务不上手表**：手腕上的内容旁人也看得到，`WatchSnapshot.make` 一开始就去掉 `finance` 插件的卡片。
- 手表上可以**勾选完成**：先在手表上打勾，再请 iPhone 去改。iPhone 在附近时用 `sendMessage` 立刻处理并回传新快照；不在附近时用 `transferUserInfo` 排队，iPhone 收到后再处理。
- 「让 iPhone 刷新」会请 iPhone 从 Mac 重新读取，再把新快照发回来；iPhone App 不在前台时，系统会在后台唤醒它处理。手表 App 打开时如果手里的数据超过 10 分钟，且 iPhone 在附近，会自己悄悄刷新一次。
- iPhone 连不上 Mac 时，「此刻」页底部显示橙色的「连不上 Mac · 多久前」，待办页底部也写明；数据超过 2 小时也会说。
- 手表 App 刚装好（或者换了一块手表）时，iPhone 收到 `sessionWatchStateDidChange`，立刻把今日快照发过去，不用等下一次刷新。
- 快照、请求、「此刻」的选择、模拟状态都在 AssistantCore（`WatchSync.swift`、`WatchMoment.swift`、`WatchMock.swift`），有单元测试；iPhone 端在 `AssistantUI/Phone/PhoneWatchBridge.swift`，手表端在 `AssistantUI/Watch/`。

### 表盘小组件

`Assistant-watchWidget`（WidgetKit）里有四种，点一下直接打开手表 App 对应的页：

- **此刻**（矩形、单行）：和 App 第一页同一件事，也是智能叠放里的样式，按 `WatchMoment.relevance` 排序。
- **下一节课**（圆形、角落、矩形、单行）：上课时显示进度和下课时间，课间是下一节和倒计时，今天的课上完后是明天第一节。
- **准备度**（圆形、角落、矩形、单行）：今日准备度的圆环，矩形带昨晚睡眠。
- **剩余待办**（圆形、角落、矩形、单行）：原来的那个，圆形多了完成进度，矩形显示最要紧的一件。

手表 App 把最新快照存进 App Group，小组件自己用它算时间线，在每个「事情会变」的时刻（上下课和课前半小时、截止前三小时和一小时、半夜、早上 5 点和 10 点、晚上 18 点和 19 点）换内容，不用等 iPhone。手表 App 收到新快照后通知小组件立即刷新。手表 App 和小组件共用 App Group `group.<前缀>`；免费的个人开发者账号如果不能用 App Group，小组件会显示「–」或提示打开 iPhone，手表 App 本身不受影响。

手表 App 是 iPhone App 的配套 App（`WKCompanionAppBundleIdentifier`，`WKRunsIndependentlyOfCompanionApp` 为否），bundle ID 是 `<前缀>.ios.watch`，小组件是 `<前缀>.ios.watch.widget`。它嵌在 iPhone App 里（XcodeGen 给 iPhone target 生成「Embed Watch Content」，复制到 `Watch/`），安装 iPhone App 时一起装上；手表 target 设了 `SKIP_INSTALL`，归档时只出一个 iPhone App。

### 在模拟器里看各种状态

调试版本启动时可以加这些参数（`xcrun simctl launch <手表> <bundle ID> -watch.mock class -page todos`），全是虚构数据，不连 iPhone：

- `-page now|todos|courses|health`：打开哪一页。
- `-watch.mock <状态>`：`class`（上课中）、`soon`（半小时内有课）、`deadline`（快截止）、`overdue`（有逾期）、`morning`（起床后）、`classes-over`（课都上完）、`all-done`（待办全部完成）、`free`（今天没安排）、`todo`（没有时间的待办）、`mac-offline`（iPhone 连不上 Mac）、`iphone-away`（iPhone 不在附近）、`stale`（两天前的快照）、`long`（很长的标题）、`live-class`（跟着真实时钟的课，看表盘用）、`no-data`（没收到过数据）。模拟器的时钟改不了，状态栏显示的是真实时间，页面按这个状态自己的时间算。
- `-watch.dim 1`：画成息屏的样子。`-watch.justDone 1`：画成刚勾掉的样子。
- `-watch.gallery 1` 或 `2`：把小组件摊开来看（矩形，圆形和单行）。

## App 图标

三端共用 `App/AppIcon.icon`，是 Icon Composer 的分层图标（iOS 26、watchOS 26、macOS 26 用液态玻璃画它）：白色的底，助理的头单独一层放在上面。默认外观是白底彩色；在主屏「自定义」里选「透明」或「色调」时，底变成透出壁纸的玻璃，头像变成玻璃质感，和系统图标一样，不会是一块白板。更早的系统用的平面图由 Xcode 编译时从它生成。可以用 Xcode 自带的 Icon Composer 打开微调。换贴图或改样子后重新生成：

```bash
swift scripts/make-app-icon.swift Design/stickers/aemeath.png App/AppIcon.icon
```

## 持续集成

`.github/workflows/frontend.yml` 只在 `frontend/` 或这个 workflow 有改动时运行，而且只在 PR 和合并到 main 时各跑一次（macOS 分钟数按 10 倍计费）：安装 XcodeGen → 生成项目 → `swift test` → 关闭签名编译 iOS（手表 App 和小组件作为它的依赖一起按 watchOS 模拟器编译，所以不再单独编译 watchOS）→ 用 `scripts/check-watch-embed.sh` 检查编译出的 iPhone App 里确实有手表 App：只有一个、bundle ID 以 iPhone App 的开头、`WKCompanionAppBundleIdentifier` 指向 iPhone App、是 watchOS 版本、带着手表小组件，同时检查 iPhone 的两个扩展（小组件和分享）的 bundle ID、扩展点和共享分组，以及分享扩展的钥匙串组配置 → 编译 macOS。
